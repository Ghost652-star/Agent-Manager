# 手动验收清单（v1.1.3）

> 目标：不用看代码，照着点一遍，确认 Workspace v2 的五块能力都真实可用。
> 预计 15 分钟。每做完一项打勾。

## 0. 准备（2 分钟）

- [ ] 解压 `AgentManager-Green-1.1.3.zip` 到 F 盘（例如 `F:\AgentManager`），双击 `Agent Manager.exe`
- [ ] 新建一个空文件夹，例如 `F:/ws-test`，往里随便放一个文件（如 `hello.txt`，内容随意）
- [ ] 顶部「项目」下拉框旁点「打开项目」，选中 `F:/ws-test`

## 1. 三个 Agent 并行 + 隔离（核心，5 分钟）

- [ ] 左侧 Agent 列表点 **Claude** → 等终端起来
- [ ] 再点一次 **Claude**（第二个会话）
- [ ] 再点 **opencode**（或其他 agent）
- [ ] 现在标签栏应有 **3 个标签**

**检查点 A —— 右侧根目录下拉框**（文件面板顶部）：
- [ ] 下拉框里有 4 项：`[默认] 项目目录`、`[工具] claude`、`[工具] claude-2`、`[工具] opencode`
- [ ] 两个 Claude 的 worktree 目录不同（悬浮提示能看到完整路径）

**检查点 B —— 磁盘上的隔离**（自己开资源管理器看）：
- [ ] `F:\agent-worktrees\ws-test\` 下有 3 个目录：`claude`、`claude-2`、`opencode`
- [ ] 每个目录里都有 `hello.txt`（新文件夹的文件被自动提交，worktree 里能看到）
- [ ] 每个目录里都有 `.agent-manager\`（scratch 目录），里面有个 `.gitignore`

**检查点 C —— 互不可见**：
- [ ] 在第一个 Claude 的终端里执行：`echo "from-claude-1" > mark.txt`
- [ ] 右侧面板切到 `[工具] claude-2` 的根目录 → 文件树里**看不到** `mark.txt`
- [ ] 切回 `[工具] claude` → 能看到 `mark.txt`，且标绿（新增）

## 2. Scratch 目录角标（1 分钟）

- [ ] 在任一 `[工具]` 根目录下，文件树里 `.agent-manager` 显示**「临时」角标**
- [ ] 它**不带**改动标色（即使 git status 里有别的文件）

## 3. 重启恢复（2 分钟）

- [ ] 完全退出 Agent Manager（关窗口）
- [ ] 重新打开，选同一个项目
- [ ] 标签栏出现**灰色的已退出标签**（和上次数量一致）
- [ ] 点其中一个灰标签 → 弹出确认 → 确认后终端重新起来，工作区还是原来那个目录
- [ ] 选根目录下拉框，能看到恢复会话对应的 `[工具]` 项还在

## 4. 审查闭环（3 分钟）

在 `[工具] claude` 根目录下（假设 `mark.txt` 还在）：

- [ ] 点右上角 **「⎇ Git 状态」** 按钮
- [ ] 浮窗里 claude 那条：能看到**改动文件数**、领先主分支的提交数
- [ ] 点**「合并回主分支」**→ 二次确认 → 成功后提示"保留 / 归档"
- [ ] 选「归档」→ 工作区从下拉框消失，磁盘上 `F:\agent-worktrees\ws-test\claude` 被删除

## 5. 拒绝误删（2 分钟）

在另一个还有改动的工作区（如 `claude-2`，先往里丢个文件）：

- [ ] Git 面板点**「丢弃全部改动」**→ 二次确认提示文件数 → 确认后工作区变干净
- [ ] 再造一个改动文件，点**「清理工作树」**→ **被拒绝**并提示有多少未提交改动
- [ ] 丢弃改动后再点清理 → 才允许删除

## 6. 外部工作区保护（可选，2 分钟）

自己在命令行造一个外部 worktree：

```powershell
cd F:\ws-test
git worktree add -b my-branch F:\ws-test-manual-wt
```

- [ ] 在软件里把这个目录「挂载为外部工作区」（根目录下拉框旁）
- [ ] 能浏览文件、能跑终端
- [ ] Git 面板里**没有**「清理工作树」按钮（外部工作区不给删）

---

## 7. 复用工作区与自动清理（v1.1.4 新增）

- [ ] 已经开过一个 Claude 会话后，再点一次 **Claude Code**
- [ ] 弹出小菜单：上面是「＋ 新建工作区」，下面是「复用已有工作区」，每项显示分支、时间和改动数
- [ ] 选「复用 claude」，终端直接落在原来那个目录，**不会**新建 claude-3
- [ ] 该工作区已有会话在跑时，再点 Claude，菜单里**看不到**它（避免两个终端写同一目录）
- [ ] 对一个干净的工作区点「合并回主分支」→ 确认 → 底部提示「已合并并清理工作目录」
- [ ] 检查磁盘：工作目录已删除，但 `git branch` 里分支还在

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动就报 `Cannot find module './workspaces'` | 1.1.1 打包白名单漏了新模块 | 换 1.1.2+（打包清单改通配符，模块齐全） |
| 启动时弹出 C 盘 Temp 路径 | 1.1.1 及以前用单文件便携 exe，运行时会自解压到临时目录 | 1.1.2+ 改为绿色版 zip，解压后原地运行 |
| 报 `No possible source branch, inferring '--orphan'` / `'--orphan' and '--track' cannot be used together` | 目标目录是 git 仓库但**一次提交都没有**（`git init` 后没 commit） | 1.1.3 已修：自动补初始提交 |
| 点 Agent 后报"不是 git 仓库" | 1.1.0 及以前没有自动 init | 1.1.2+ 已加自动 `git init` + 首次提交 |
| 根目录下拉框只有 [默认] | 还没启动过 agent | 先点 Agent 列表启动一个 |
| 恢复点不动 | 工作区目录被手删了 | 弹窗会明确提示"目录已丢失"，关掉标签即可 |
